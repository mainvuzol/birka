Запусти агента `birka-redesign-strategist`.

Объём: $ARGUMENTS (пусто — всё приложение по таблице навигации эталона, начиная с каркаса и самых частых экранов; весь код за один заход не читается, поэтому при большом объёме разбей на несколько запусков по разделам).

Режим: А «переписать под дизайн» по `.ai/project-memory/redesign/design-direction.md`. Если в аргументах есть «этап 2» — режим Б: спроектировать недостающие разделы в той же системе и пометить их «нужно утверждение».

Агент стартует с чистого контекста и не может задавать вопросы, поэтому в его задачу впиши объём, режим и сегодняшнюю дату. Аудит идёт по коду и e2e-спекам, без запуска приложения. Если пользователь просит скриншоты, скажи, что для них нужен отдельный стенд (API, PostgreSQL 17, e2e-фикстура), и предложи сделать их отдельным шагом после ТЗ: временный контейнер поднимается только после явного «да», dev-базу разработчика не трогать.

Когда агент закончит: перескажи резюме, P0 и вопросы владельцу, дай ссылки на ТЗ и на документ для владельца. Код не меняй, пока пользователь не выберет задачи; работу по выбранным задачам веди через `.ai/skills/executive-orchestrator.md`.
